# Editorial Operating System Runbook

## 1. Set up the project

Complete the project brief and novel bible in `shared/assets/`. Record genre, audience, POV, tense, style preferences, nonnegotiable choices, known research risks, and the current revision stage.

## 2. Choose the review unit

Use scenes for line, dialogue, or realism work; chapters for pacing and character work; acts or the full manuscript for developmental, continuity, ending, and publishing review.

## 3. Run reviewers independently

Never show one reviewer another reviewer’s report before it produces its own findings. Use the same manuscript version and project materials for every reviewer in the round.

## 4. Synthesize

Give all independent reports to `editorial-director`. The director clusters duplicates, preserves dissent, identifies root causes, and creates a revision order.

## 5. Decide

The author accepts, modifies, defers, or declines each issue. Record the decision in the issue ledger. A taste note is not a command.

## 6. Revise and verify

After revision, run `revision-verifier` against the old issue IDs and the new text. Mark issues fixed, partially fixed, displaced, unchanged, worsened, or intentionally declined.

## 7. Update memory

Update canon only when the manuscript establishes it. Keep historical issue records. Never delete an old issue simply because it was fixed.

## Recommended order by draft stage

- Early draft: developmental editor, character-arc reader, continuity auditor.
- Middle draft: pacing, dialogue, emotional impact, relevant subject-matter experts.
- Late draft: line editor, copy editor, continuity pass, series-ending reader.
- Submission draft: literary-agent reader, acquisitions reader, positioning reader, submission-package auditor.
