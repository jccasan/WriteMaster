# DEPRECATED: Editorial Operating System v1.0.0

Superseded by Editorial Operating System v2.0.0, installed at `config/editorial-os/`.

This directory is retained for reference only. Nothing here is loaded at runtime.

## Contents

- `config/` was `config/editorial-os/`, the 43 file v1 package.
- `oracle-veil/` was `data/editorial-os/oracle-veil/`, the 22 file v1 project pack.

## Why v1 was retired

v1 supplied the novel bible to every skill in the package, including the seven
reader panel skills.

The reader panel exists to produce one thing: the experience of a person who
does not know what happens next. A reader that has read the bible knows the
immortality reveal, knows the Book 2 architecture, and knows the answers to the
questions the manuscript is withholding. It cannot report a first read. Its
"I saw this coming" is a memory of the bible, not a reaction to the pages, and
its "this landed" confirms whatever the bible already said the scene was for.

v2 closes this with `shared/references/INPUT_CONTRACT.md`, which bars family C
from the novel bible, the project brief, the style sheet, the issue ledger,
prior reviewer reports, author intent statements, series outlines, and any
description of what a scene is supposed to accomplish. A v2 reader skill
invoked with barred material in context outputs `CONTAMINATED INPUT` and
refuses.

## Status of v1 reader panel output

Any reader panel output in this repository that was produced under v1 should be
treated as contaminated. Do not use it as evidence in a revision decision. This
applies to the reports themselves and to any downstream document that cites
them, including issue ledger rows sourced from a v1 reader.

The contamination is not visible in the output. A bible fed reader produces a
report that reads as more confident and better informed than a clean one, which
is why it must be excluded on provenance rather than on how it reads.
